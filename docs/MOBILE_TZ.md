# ТЗ — мобильное приложение Pragmata AI (React Native)

> Одностраничное техзадание для мобильного разработчика. Можно использовать и как
> промпт для AI-инструмента. Все эндпоинты — реальные, из работающего бэкенда
> (FastAPI, `/api/v1`, полная схема — `openapi.json` в корне репо).

---

## 1. Что за продукт

**Pragmata AI** — «умный охранник» поверх уже установленных камер видеонаблюдения.
Сервер (on-prem или облако клиента) сам анализирует видео 24/7: распознаёт людей и
транспорт, ловит нарушения (вход в запретную зону, оружие, огонь, толпа, оставленные
предметы, СИЗ и т.д.), присылает тревоги и умеет отвечать на вопросы на узбекском.

**Мобильное приложение — это приложение оператора/владельца объекта.** Главная
ценность: **мгновенные тревоги в кармане** + живой просмотр камер + лента событий с
доказательствами (фото/клип) + AI-ассистент. Аналог веб-дашборда, но заточенный под
телефон и push-уведомления.

Целевой пользователь: охранник/оператор поста, руководитель/владелец бизнеса
(ритейл, склад, школа, офис, парковка).

---

## 2. Стек и принципы

- **Expo (managed) + TypeScript**, dev-build (для нативных push). React Native 0.7x.
- **React Navigation** (stack + bottom tabs).
- **TanStack Query** (@tanstack/react-query) — весь сетевой слой, кэш, инвалидция
  (веб уже на нём — переносим логику 1:1).
- **i18next / react-i18next** — 3 языка: **uz (по умолчанию), ru, en**.
- **expo-secure-store** — хранение JWT-токена (НЕ AsyncStorage для токена).
- **expo-notifications** (+ FCM/APNs через dev-build) — push.
- Тема **светлая/тёмная**, дизайн-паритет с вебом (токены ниже).
- Код на функциональных компонентах + хуках, строгий TS, без `any`.

Принцип: **сервер — источник правды**. Приложение ничего не решает само; права,
данные, тревоги — всё с сервера.

## 3. Бэкенд и авторизация

**Base URL** задаётся в настройках сборки (env), напр. `EXPO_PUBLIC_API_URL`.
Все запросы (кроме логина) — заголовок `Authorization: Bearer <token>`.

**Флоу входа:**
1. `POST /api/v1/auth/login` `{username, password, code?}` →
   `{access_token, token_type, role, username, mfa_required}`.
2. Если `mfa_required === true` и в ответе `access_token` пустой — показать шаг ввода
   **TOTP-кода** и повторить логин с полем `code`.
3. Токен сохранить в **SecureStore**. При старте — если токен есть, идём в приложение.
4. Любой ответ **401** → чистим токен, разлогин, экран входа.
5. `GET /api/v1/me` → `{sub, username, role, site_id, backoffice, entitlements}`.

**entitlements (ВАЖНО — гейтинг по подписке):**
```json
{ "all": false, "tariff": "school",
  "modules": ["zone_intrusion", "..."],
  "features": ["assistant","journal","watchlist","heatmap","stats","turnstile", "..."],
  "person_categories": ["employee","watchlist"], "limits": {} }
```
- `all: true` → доступ ко всему (владелец платформы), ничего не прячем.
- Иначе: **разделы (табы/экраны) показываем только если их ключ есть в `features`.**
  Ядро (обзор/камеры/события) — всегда. Гейтятся: `assistant`, `journal`,
  `watchlist`, `heatmap`, `stats`, `turnstile`.
- В форме реестра людей категории — только из `person_categories` (напр. в «Школе»
  нет «Гостя»/`visitor`).

Прочее по аккаунту: `PATCH /api/v1/me/password`, 2FA — `GET/POST /api/v1/me/2fa/setup|enable|disable`.

## 4. Экраны (bottom-tabs + stack)

Нижние табы (набор зависит от `features`): **Обзор · Камеры · События · Ассистент · Ещё**.

### 4.1 Login
Поля username/password, второй шаг — TOTP-код. Логотип-диафрагма (бирюза), слоган
«Kameralaringiz uchun aqlli qo'riqchi». Ошибка входа — понятный текст.

### 4.2 Обзор (Overview) — `GET /api/v1/overview`
Карточки-метрики: людей за 24ч, тревог, «неверных сигналов», камер онлайн (X/Y).
График почасовой активности (события/тревоги). Список последних тревог (тап →
детали события). Pull-to-refresh. Автообновление ~15–30 с.

### 4.3 Камеры (Live) — `GET /api/v1/cameras`
Сетка карточек камер: снапшот (`snapshot_url` или `GET /api/v1/cameras/{id}/snapshot`),
имя, статус **онлайн/офлайн** (зелёный/серый). Снапшот обновлять раз в ~3–5 с (poll,
т.к. RTSP-стрим на телефон в MVP не тянем). Тап → полноэкранный просмотр камеры +
кнопка «События этой камеры».
> Медиа/снапшоты требуют `Authorization` — грузить через fetch с Bearer (см. §6).

### 4.4 События (Events) — `GET /api/v1/events`
Лента (серверная пагинация): миниатюра-кадр, тип события (лок. название), **цвет по
severity** (info/warning/alert), зона, время. Фильтры сверху: период (24ч/7д),
тип, важность. Бесконечный скролл, pull-to-refresh.
Тап → **детали события**: крупное фото (`/events/{id}/photo`), лицо
(`/events/{id}/face`), клип 30с (`/events/{id}/clip`), метаданные, кнопки
«Ложная тревога/Подтвердить» (`POST /events/{id}/feedback`).
Экспорт отчёта (опц.): `GET /api/v1/events/report.pdf`.

### 4.5 Ассистент (Yordamchi) — `POST /api/v1/agent/ask` *(feature: assistant)*
Чат: поле ввода, вопрос на узбекском («Kim taqiqlangan zonaga kirdi?»), ответ
приходит текстом + **evidence-фото** (грид кадров-доказательств). Стартовые
чипы-подсказки. Проверка доступности — `GET /api/v1/agent/enabled`.
Тело: `{question, session_id}`; ответ `{text, evidence:[{caption, photo_url, clip_url}]}`.
Markdown в ответе (таблицы/жирный) — рендерить лёгким markdown.

### 4.6 Журнал входов/выходов — `GET /api/v1/appearances` *(feature: journal)*
Список визитов (вход→выход) с именем у распознанных (Face ID): фото, имя/категория,
камера, время входа/выхода, длительность.

### 4.7 Реестр людей (Odamlar) — `GET /api/v1/persons` *(feature: watchlist)*
Список людей (сотрудники/гости/чёрный список) с фильтром по категории (только из
`entitlements.person_categories`). Регистрация по фото — `POST /api/v1/persons/enroll`
(multipart: имя, категория, фото). Детали/фото — `/persons/{id}`, `/persons/{id}/photos`.

### 4.8 Статистика — `GET /api/v1/stats` *(feature: stats)* + дайджест `GET /api/v1/digest`
Диаграммы (по типам/времени) + «Kunlik xulosa» (дневная сводка).

### 4.9 Турникеты — `GET /api/v1/turnstiles` *(feature: turnstile)*
Список турникетов (имя, режим, коннектор, камера). Кнопка **«Открыть»**
(`POST /api/v1/turnstiles/{id}/open`) — с подтверждением (физическое действие!).

### 4.10 Ещё / Настройки
Язык (uz/ru/en), тема, смена пароля (`PATCH /me/password`), 2FA, **привязка
Telegram** (`POST /api/v1/telegram/bind-code` → показать код для бота), выход.
Для роли `admin` — переключатель организаций (заголовок `X-Site-Id`, список
`GET /api/v1/backoffice/sites`).

## 5. Push-уведомления (ключевая ценность)

Тревога должна прилетать **мгновенно**, как в Telegram.

- **MVP (без изменений бэкенда):** foreground/near-real-time — poll `GET /api/v1/events`
  каждые ~15 с, на новые события severity `alert`/`warning` показывать **локальное
  уведомление** (expo-notifications), тап → экран деталей события. Плюс уже есть
  Telegram-канал (привязка через `telegram/bind-code`) как запасной путь.
- **Фаза 2 (нужен бэкенд):** нативный server-push (FCM/APNs). Требуется добавить на
  бэкенд: (а) регистрация device-token (`POST /api/v1/me/push-token`), (б) отправка
  push при создании тревоги. **Заведите это как задачу бэкенду — эндпоинтов пока нет.**
- Дедуп/тихие часы/группировка по камере — на клиенте.

---

## 6. Медиа (авторизованное)

Кадры, лица, клипы, снапшоты отдаются с проверкой `Authorization`. Нельзя вставлять
URL напрямую в `<Image>` без заголовка. Варианты:
- fetch с Bearer → blob → локальный uri, ИЛИ `expo-image` с `headers`.
- Универсальный медиа-эндпоинт: `GET /api/v1/media?p=<path>&kind=photo|clip`.

## 7. Брендинг и дизайн-токены (паритет с вебом)

- **Бренд-бирюза `#0D9488`** (логотип-диафрагма, акценты, активный таб).
- Severity: **info** — нейтральный/синий, **warning** — янтарный `#D97706`,
  **alert** — красный `#DC2626`.
- Тёмный текст `#0E1B33`, вторичный `#5B6B7A`.
- Логотип — апертура (6 лепестков), есть SVG в `docs/brand/`.
- Скругления, тени, скелетоны при загрузке; состояния empty/error/loading на каждом
  экране (не голый спиннер).

## 8. Нефункциональные требования

- **Приватность:** видео/лица не покидают объект; приложение работает с API сервера
  клиента. Не логировать персональные данные.
- Токен — только в SecureStore; при 401 — авто-логаут.
- Оффлайн/плохая сеть: кэш TanStack Query, ретраи, дружелюбные ошибки.
- Пагинация везде, где списки; pull-to-refresh; оптимистичные апдейты где уместно.
- Поддержка iOS и Android; минимальная версия — по договорённости.

## 9. Объём и этапы

**MVP (фаза 1):** Login(+2FA) · Обзор · Камеры(снапшоты) · События(лента+детали+фото/клип)
· Ассистент · Push через poll+локальные уведомления · Настройки(язык/тема/выход) ·
гейтинг по `entitlements`.

**Фаза 2:** Журнал · Реестр людей(+enroll по фото) · Статистика/дайджест · Турникеты ·
нативный FCM-push · переключатель организаций для admin · привязка Telegram.

---

## 10. Критерии приёмки

- Вход по username/password (+TOTP), токен в SecureStore, авто-логаут на 401.
- Разделы строго по `entitlements.features` (проверить на тарифе «Парковка»: видны
  только базовые + без ассистента/Face ID; на «Школе» — без категории «Гость»).
- Тревога → локальное уведомление за ≤ ~20 с (MVP), тап открывает событие с фото.
- 3 языка переключаются на лету; светлая/тёмная тема.
- Все списки — пагинация + pull-to-refresh; на каждом экране — loading/empty/error.
- Медиа грузится с авторизацией (не 401).
