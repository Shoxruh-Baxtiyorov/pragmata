**Одной строкой:** AI-аналитик безопасности поверх уже установленных камер — сам следит, сам докладывает в Telegram, отвечает на вопросы на узбекском/русском и находит человека по описанию за секунды.

**Позиционирование:** не «video analytics» (там Verkada/Rhombus/Hikvision/Axis), а **AI Security Copilot**: «мы автоматизируем не камеры, а принятие решений». Для клиента: «4 часа перемотки → 20 секунд». Для жюри: агентная архитектура поверх собственного CV-пайплайна.

## 1. Архитектура

```
                ┌──────────────────────── EDGE-БОКС (у клиента, on-prem) ────────────────────────┐
Камеры RTSP ─┐  │                                                                                 │
mp4 (dev) ───┼─▶│ VideoSource ▶ Motion Gate ▶ YOLO ▶ ByteTrack ▶ Rule Engine ─▶ события          │
телефон ─────┘  │      │                                │  │           │            │             │
                │      ▼                                │  ▼           ▼            ▼             │
                │  Ring Buffer (H.264)          face-кропы  CLIP-эмб.  VLM      Postgres          │
                │      │                            │  (L0/L1)  │  (селективно)  + pgvector       │
                │      ▼                            ▼           ▼       │            │             │
                │   клипы ────────────────────▶  MinIO  ◀──────┘        └──────────▶│             │
                │                                                                    │             │
                │              АГЕНТ (LLM + typed tools: SQL / vector / media)  ◀───┘             │
                └───────────────┬──────────────────────────────┬──────────────────────────────────┘
                                ▼                              ▼
                         Telegram-бот                    Web-дашборд
                  (алерты · чат · дайджест · FP)   (зоны · лента · investigation)
```

Девять слоёв, с решениями-мелочами:

**1. VideoSource (интерфейс).** Реализации: RTSP (транспорт TCP — UDP теряет кадры), mp4-loop (dev), MJPEG с телефона (IP Webcam), USB. Auto-reconnect с backoff 1→2→4…→60 с, health-статус (возраст последнего кадра, fps). Обработка с шагом: декодируем нативно, в детекцию отдаём ~5 fps. Время: штампуем серверным receive-time (часам камер не верим), в БД всё в UTC, показ в Asia/Tashkent, NTP на боксе обязателен.

**2. Motion Gate.** Дешёвый детектор движения (grayscale 320px, MOG2/absdiff) перед YOLO: нет движения N секунд → детекцию не гоняем вообще (ночью экономит почти всё). Чувствительность per-camera.

**3. Ring Buffer + клипы.** ffmpeg `-c copy` (без транскода!) пишет 2-секундные сегменты, кольцо на 5–10 минут на камеру (при 1080p/2 Мбит ≈ 75–150 МБ — копейки). Клип события = склейка сегментов [T−10 с, T+20 с] → mp4. Никакого перекодирования — CPU свободен.

**4. Perception.** YOLO11n/s (только класс person в MVP), батчинг кадров со всех камер в один проход GPU; ByteTrack — стабильные track_id внутри камеры; фильтр коротких треков <0.7 с (анти-фликер). Best-frame трека = резкость (Лаплас) × площадь bbox. Лица: L0 — SCRFD-детекция внутри person-bbox, скоринг качества (blur/поворот/размер ≥48px), лучший кроп прикрепляется к событию как фото-доказательство (это НЕ распознавание). L1 (stretch) — ArcFace-эмбеддинг, онлайн-кластеризация (cos ≥ ~0.55) → анонимный «Человек #17», ночной re-cluster; TTL на кропы/эмбеддинги. CLIP ViT-B/32 эмбеддинг person-кропа (один на трек) → pgvector — топливо Investigation Mode. Мощности: Victus RTX тянет 5–8 камер @5 fps с запасом; дизайн-цель 16 камер на десктопной 3060.

**5. Rule Engine (детерминированный, фабрика событий).** Вход: треки + зоны (полигоны per-camera, проверка по bottom-center bbox) + календарь. Анти-спам везде: hysteresis (событие после N подряд кадров, не одного), cooldown (одно zone-событие на трек в 5 мин), merge эпизодов (разрыв <15 с = одно событие). Severity: info / warning / alert → матрица маршрутизации (мгновенно / в дайджест / только в БД).

**6. VLM-слой (селективный).** Триггер: только severity ≥ warning или типы из конфига. Вход: 3–5 ключевых кадров. Выход structured (function calling): описание ru/uz, теги, уточнённый severity и **fp_hint** — «это тень/кошка/блик» → авто-даунгрейд ДО того, как разбудили человека (VLM как фильтр ложняков — дешёвое второе мнение). Лимит вызовов/час на объект, переполнение — в очередь. Провайдер через OpenRouter: free-модели на dev, env-switch на платные, fallback-цепочка.

**7. Хранилище.** Postgres 16 + pgvector (события, треки, персоны, зоны, камеры, feedback, эмбеддинги); MinIO (кадры/кропы/клипы, TTL 30 дней конфигурируемо); Redis (очереди VLM-джобов, pub/sub для live-дашборда). События — маленькие строки, храним год+; disk guard: лимит ГБ на камеру, eviction старых, алерт при 90%.

**8. Агент.** LLM с типизированными инструментами (SQL-first, НЕ text-to-SQL — никаких галлюцинированных колонок и инъекций): `search_events(время, камера, зона, тип, severity, person_id)`, `semantic_search_events(текст)` (pgvector по описаниям — для нечётких «что-то странное было?»), `find_person_by_description(текст, интервал)` (CLIP — Investigation), `person_timeline(person_id, дата)`, `get_clip/get_frame(event_id)`, `camera_status()`, `stats(период, разрез)`. Агент read-only (виды БД), понимает uz/ru, держит контекст последних N реплик («а покажи клип» после ответа работает). Ответ = текст + медиа-альбом.

**9. Delivery + Ops.** Telegram-бот (aiogram 3) — главный UI; web-дашборд (React+Vite) — вторичный. docker-compose на одном GPU-боксе: core (ingest+perception+rules), api (FastAPI), bot, worker (VLM/дайджест/ретеншн), postgres, redis, minio, mediamtx (dev), dashboard. CPU-only режим (меньше камер) — чтобы демо жило и без GPU. Для показа жюри — Cloudflare-туннель к дашборду. Backup: ночной pg_dump + конфиги (клипы не бэкапим). Секреты в env, RTSP-креды в БД шифруются (Fernet — опыт есть). Лицензия (подписанный файл с expiry) и OTA-обновления — после конкурса.

**Стек** (весь — ваши рабочие навыки): Python 3.12 + uv, FastAPI, SQLAlchemy + Alembic, aiogram 3, ultralytics + supervision, insightface, open_clip, ffmpeg, Postgres + pgvector, Redis, MinIO, React + Vite + Tailwind, docker-compose. Новое для вас только supervision/open_clip — API тривиальные.

## 2. Схема данных (ядро)

- `sites` — объект: название, timezone, рабочий календарь (часы + праздники), настройки дайджеста.
- `cameras` — site_id, имя, url (шифр.), настройки (fps, conf, motion), статус, uptime.
- `zones` — camera_id, полигон (нормализованные координаты), тип (restricted/counting/interest), параметры правил.
- `tracks` — camera_id, t_start/t_end, сводка траектории, best_crop, face_crop, quality, clip_path, clip_emb (CLIP), face_emb (L1).
- `persons` (L1) — анонимный кластер: центроид, метка «Человек #N» (переименовываемая), first/last_seen, счётчик появлений.
- `events` — тип, severity, camera/zone, t_start/t_end, track_ids[], person_ids[], пути к кадру/кропу/клипу, description (VLM), desc_emb, meta jsonb.
- `feedback` — event_id, вердикт (ложное/подтверждено), кто, когда.
- `chats` — telegram chat_id, роль (owner/security/viewer), site_id.
- `digest_log`, `audit_log` (кто смотрел какой клип).

## 3. Жизнь одного события (walkthrough)

19:43, склад закрыт с 18:00.

1. Кадр с камеры 4; motion gate видит движение → кадр идёт в пайплайн.
2. YOLO: person 0.87 → ByteTrack даёт track #317.
3. Bottom-center bbox внутри полигона «Склад-вход» 12 кадров подряд (hysteresis 10) → Rule Engine рождает `zone_intrusion` + параллельно `after_hours_presence`; merge → одно событие severity=alert; cooldown на трек взведён.
4. Из ring buffer склеивается клип [19:42:50 → 19:43:30] без транскода; выбран best-frame; SCRFD нашёл лицо → кроп сохранён (L0).
5. Медиа в MinIO, событие в Postgres, CLIP-эмбеддинг кропа в pgvector.
6. severity=alert → VLM смотрит 4 кадра: «мужчина в тёмной куртке вошёл через ворота, несёт коробку», fp_hint: нет → severity подтверждён, описание в событие.
7. Бот шлёт карточку owner'у и охране: фото + «19:43 · Камера 4 · Вход в зону после закрытия» + кнопки [🎬 Клип] [📍 Таймлайн] [⚠️ Ложное] [✅ Ок].
8. Директор жмёт [Клип], смотрит, пишет: «bu odam bugun yana qayerda bo'lgan?» → агент → `person_timeline` → альбом появлений по камерам.
9. В 20:00 событие попадает в вечерний дайджест со статистикой дня.
10. Если это оказался сторож — директор жмёт [⚠️ Ложное] → запись в feedback → ночной джоб предложит правку правила («сторож ходит в 19:40 ежедневно — добавить исключение по расписанию?»).

## 4. Полный функционал MVP — каждая мелочь

### A. Камеры и подключение
1. Добавление камеры по RTSP URL + кнопка «проверить» (снапшот-превью до сохранения).
2. Источники: RTSP / mp4-файл / MJPEG с телефона / USB — один интерфейс.
3. Auto-reconnect с экспоненциальным backoff; события `camera_offline`/`camera_online` (реальная боль клиентов: камера умирает, узнают через месяц).
4. Health-монитор: fps, возраст последнего кадра, uptime% — команда `/status` в боте.
5. Per-camera настройки: fps детекции, порог confidence, чувствительность motion, включённые правила.
6. Мульти-камера на одном боксе: демо 3–5, дизайн до 16.

### B. Детекция, трекинг, лица
7. Детекция людей (YOLO11), пороги per-camera.
8. Трекинг со стабильными track_id; фильтр треков <0.7 с (анти-фликер).
9. Best-frame на трек: резкость × размер (для карточек и VLM).
10. **L0-лица:** детекция + кроп лучшего лица как фото-доказательство события. Не распознавание — приватность-риск ~0.
11. **L1 (stretch):** анонимная кластеризация → «Человек #17» сквозь камеры и дни; переименование вручную («Санжар-охранник») — опционально per-site.
12. CLIP-эмбеддинги person-кропов (один на трек) — база Investigation Mode.
13. Зоны-полигоны per-camera; типы: запретная / счётная / интересная.

### C. Правила и события
14. `zone_intrusion` — вход в запретную зону (hysteresis N кадров, cooldown на трек).
15. `loitering` — присутствие в зоне/камере ≥ T минут.
16. `after_hours_presence` — человек вне рабочих часов (календарь объекта + праздники).
17. `person_entered/exited` + дневной счётчик посетителей per-camera.
18. `crowding` — ≥ N человек в зоне (тривиальный счётчик, но продаёт).
19. `camera_offline/online`.
20. `unknown_person` (только с L1) — кластер, которого раньше не было.
21. Severity info/warning/alert + матрица маршрутизации (мгновенно / дайджест / только лог).
22. Merge эпизодов: один человек в зоне = одно событие, не 50 алертов.
23. Cooldown per правило × камера × трек.
24. Каждое событие несёт: фото, кроп лица (если есть), клип, времена, камеру/зону, ссылки на треки/персоны.

### D. Клипы и хранение
25. Кольцевой буфер H.264 copy (без транскода), клип = [T−10 с, T+20 с].
26. MinIO + TTL: клипы/кропы 30 дней (конфиг), события в БД — год+.
27. Disk guard: лимит на камеру, вытеснение старых, алерт при 90%.
28. Ретеншн-политика видна в настройках (важно для приватность-питча).

### E. VLM-слой
29. Селективные описания флагнутых событий (3–5 кадров → структурный JSON: описание ru/uz, теги, severity, fp_hint).
30. **VLM-фильтр ложняков:** «тень/животное/блик» → авто-даунгрейд до того, как потревожили человека.
31. Бюджет-лимиты вызовов (час/день на объект), переполнение в очередь.
32. OpenRouter: free на dev, env-switch на прод, fallback-цепочка моделей.

### F. Агент (чат)
33. Свободные вопросы на uz/ru; примеры, которые обязаны работать на демо:
    - «Kim 18:00dan keyin kirdi?» → search_events
    - «Bugun nechta odam keldi?» → stats
    - «3-kamera 14:00–15:00 nima ko'rdi?» → выборка + сводка
    - «Shu odamning hamma harakatini ko'rsat» (реплаем на фото) → person_timeline
    - «Qora kurtka, oq ryukzak, 15:00–16:00 — top» → CLIP-поиск
    - «Kecha g'alati narsa bo'ldimi?» → semantic search по severity≥warning
34. Ответ = текст + фото/клипы альбомом; контекст диалога (follow-up работает).
35. Агент read-only; админ-действия только командами с whitelist chat_id.

### G. Уведомления и дайджест
36. Карточка алерта: фото + что/где/когда + [🎬 Клип] [📍 Таймлайн] [⚠️ Ложное] [✅ Ок].
37. **Вечерний дайджест** (время конфиг, деф. 20:00): LLM-сводка дня, топ-инциденты (фото лица + время + клип), статистика (посетители, пики, по камерам), незнакомцы (L1), health камер, счётчик ложняков.
38. `/mute 1h|today` — тишина для warning; alert пробивает всегда.
39. Роли получателей: owner (всё) / security (алерты) / viewer (дайджест).
40. Недельный дайджест с трендами (stretch).

### H. Качество и обратная связь
41. Кнопка «⚠️ Ложное» → запись в feedback.
42. Ночной джоб: FP-отчёт по правилам/камерам + предложения порогов («cam3 zone_intrusion: 40% FP — поднять hysteresis до 15?») — применение одной кнопкой.
43. FP-кадры копятся как регрессионный набор для тюнинга.
44. Метрики качества в дайджесте: отправлено / подтверждено / ложных.
45. **Golden-set в CI:** 10 размеченных клипов → оффлайн-прогон пайплайна → assert ожидаемых событий. (Жюри будет читать GitHub — это отличает инженеров от вайб-кодеров.)

### I. Investigation Mode (гвоздь демо)
46. Запрос: описание внешности текстом + интервал + камеры → топ-K кандидатов (CLIP-поиск по кропам).
47. Галерея кандидатов → клик → все появления человека, таймлайн, клипы.
48. Сбор находок в «расследование» → **экспорт PDF** (weasyprint — опыт Iqbola): титул объекта, хронология со скринами, камеры, времена — готовый акт для руководства/милиции. Шаблоны uz/ru. (Только если слак в неделе 4.)

### J. Web-дашборд (тонкий)
49. Live-стена: последние кадры камер, обновление 1–2 с по WebSocket (НЕ видеостримы — WebRTC жрёт время, кадров достаточно).
50. Лента событий с фильтрами (тип/камера/severity/дата) + плеер клипов.
51. Таймлайн человека/трека по камерам («Человек #24: 09:14 кам.2 → 09:17 кам.5 → 09:40 вышел»).
52. Редактор зон: полигоны поверх снапшота (canvas), параметры правил на зону, hot-reload без рестарта.
53. Календарь рабочих часов + праздники.
54. Статистика: посещаемость по дням/часам, события по типам.
55. Настройки: камеры, ретеншн, маршрутизация алертов. Auth: один админ, JWT.

### K. Приватность и безопасность (питч-критично)
56. Всё on-prem: видео и лица не покидают объект; наружу — только текстовые события (и то опционально).
57. TTL и авто-удаление биометрии; анонимные ID вместо имён (L1); именованные identity — только L2 после конкурса, с consent-процессом.
58. Audit log: кто смотрел какой клип.
59. Секреты в env; RTSP-пароли шифруются в БД.
60. Одностраничный «паспорт данных» (что храним, где, сколько) — для директора/юриста.

### L. Ops
61. `docker-compose up` на одном GPU-боксе; CPU-fallback режим.
62. Self-monitoring: живость воркеров, GPU-память, диск; health-endpoint.
63. Ночной pg_dump + конфиги.
64. i18n бота: строки uz/ru из YAML, не хардкод.
65. Seed-скрипт демо-данных (снимать видео-питч, не дожидаясь живых событий).

### M. Материалы конкурса (это тоже функционал)
66. GitHub: чистый публичный репо, README на uz/ru/en, архитектурная диаграмма, demo-GIF'ы, LICENSE (proprietary/BUSL), .env.example, никаких секретов в истории.
67. 3-минутный видео-питч (сценарий ниже).
68. Дека 10–12 слайдов × 3 языка + лого.
69. Постановочные демо-сцены (дом/колледж): вход в зону после закрытия, «потерянный телефон» для Investigation, обычный день для дайджеста.
